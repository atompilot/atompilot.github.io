Gemini CLI 已对消费级用户停服

Google 在 2026-05-19 I/O 宣布，Gemini CLI 与 Gemini Code Assist IDE 扩展自 2026-06-18 起停止为 Google AI Pro、Ultra 及免费个人用户提供服务，继任者是闭源、Go 写的 Antigravity CLI（二进制 agy）。企业版 License 与付费 API Key 不受影响。任何还在推荐 Gemini CLI 的文章都已过期。

生效 2026-06-18 · Google 官方公告

Claude 订阅能不能驱动第三方：分两种情况

流传最广的说法「Claude 订阅一律不能用于第三方」已经不准确。真实边界是：直接拿订阅 OAuth token 打 Anthropic API 的第三方 harness 仍被禁——Agent SDK 官方文档原话是「除非事先批准，Anthropic 不允许第三方开发者为其产品提供 claude.ai 登录或速率限制」；但通过 claude -p 或 Agent SDK 包装的本地个人工具属于允许范围。更关键的是：原定 2026-06-15 把这类程序化用量拆进独立信用池的计费改动，Anthropic 已于当日宣布暂停、并未生效，因此它们目前仍然照常吃订阅额度。官方称会重做方案并提前通知。

订阅额度还是 API 计费

同一个 CLI，用订阅登录和用 API Key 登录的成本可以差一个数量级——API 是按公开费率全价计量，订阅是包月。所以选型时真正该问的不是「这个工具多少钱」，而是「我已有的订阅能不能喂给它」。下表按这个口径分四类。价格与政策截至 2026-07-30，均取自各家官网或官方文档。

② 第三方 CLI 能不能用大厂订阅 —— 两家政策完全相反

OpenAI：可以，且被明确支持

opencode v1.1.11（2026-01-10）加入 Codex OAuth，/connect 即可登录 ChatGPT Plus / Pro；Cline 官方发文「Bring your ChatGPT subscription to Cline」；OpenAI 与 Roo Code 有官方合作。HN 上的说法是 OpenAI 员工在公开渠道明确认可 pi、opencode 等第三方 agent 使用 Codex OAuth。唯一的软肋是这件事至今没有写进正式条款文档，全靠员工发言与产品行为佐证，社区一直在要一个白纸黑字的说法。

Anthropic：看你怎么接

不允许：第三方 harness 直接拿订阅 OAuth token 打 Anthropic API。Agent SDK 文档写得很清楚——「除非事先批准，Anthropic 不允许第三方开发者为其产品提供 claude.ai 登录或速率限制，包括基于 Claude Agent SDK 构建的 agent」。
允许：把 claude -p（headless）或 Agent SDK 当后端来包装的本地个人工具。原定 2026-06-15 将这类程序化用量拆进独立信用池（Pro $20 / Max 5x $100 / Max 20x $200，按 API 全价计量、不滚存）的改动，已在当日被 Anthropic 宣布暂停、未生效，目前仍照常吃订阅额度。

③ 模型侧订阅 —— 降本最狠的一档，也最容易被忽略

这类订阅卖的是模型额度而非工具，能挂到多种 CLI 上，是「不换工具只换钱包」的路子。

④ 只能自带 API Key —— 工具免费，模型全价

Pi、Goose、Crush、Aider、Continue、OpenHands 属于这一类：软件本身不要钱，但每一个 token 都按 provider 公开费率付。Amp 是其中的特例——同为按量付费，但个人与团队零平台加价、$5 起充，成本结构最透明。这一类真正的省钱办法不是换工具，而是把它们指向上面第 ③ 类的便宜模型订阅，或指向本机 Ollama。

社区实际怎么说

以下取自 Reddit（r/codex、r/ClaudeCode、r/ClaudeAI、r/opencode、r/cursor、r/LocalLLaMA）与 Hacker News 的一手用户发言，只保留反复出现、且指向具体机制的说法，一次性吐槽和明显的推广贴已剔除。这是主观口碑，不是评测结论——同一款工具在不同人手里的评价经常是反的。

Claude Code ↔ Codex：一场以「额度」为主因的迁徙

共识：模型轮流领先，工具体验一边倒。

  • 迁走的主因几乎都是用量限制，不是能力。反复出现的说法是即便 Max $100 档也能在几天内烧完周额度；有人称 GPT-5.5 high 的用量消耗比 Sonnet 4.6 medium 少 2–4 倍，因此「两个 Max 20x 账号降级成一个 $100 的 ChatGPT」。
  • Codex 被夸的点：更守指令、后端与调试强、不绕圈子、开源、OpenAI 多次重置限额被视为「对客户更好」。
  • Codex 被骂的点：TUI 体验差（有人直言「Rust 的 TUI 库生态还不到位」）、diff 显示难读——这条对「要逐条审批改动」的人是致命伤；插件不能从 Claude Code 平移，得重写；慢；从零起项目弱；固执，认定一个方向后不肯回头重审假设。
  • Claude Code 被夸的点：CLI 体验「甩开一个身位」、subagent、skill/plugin 生态、diff 可读、会解释自己为什么这么做（便于在跑偏早期叫停），前端与既有代码库理解更好。
  • 高频结论是「都订，换着用」，并且出现了一个反复被提到的固定搭配：Codex 高推理档做规划与代码审查，Claude 做实现。还有人把它做成自动循环直到干净再提 PR。
  • 有人总结得挺准：「5.5 现在是更好的编码模型。下个月大概又是 Claude 领先。习惯换模型吧。」

opencode：赞誉与不信任并存

共识：体验超前，工程稳健度和隐私姿态拖后腿。

  • 被夸：TUI 比 Claude Code 舒服（「不像 CC 那样往你脸上糊大段文字」）、不动不动要权限、实时显示 diff、LSP 驱动的自愈循环好用、自定义 agent 灵活；Zen/Go 便宜档加上白给的开源前沿模型额度，被不少人视作「退订 Claude 的理由」。
  • 被骂最狠的是稳定性：启动卡死、发消息后 UI 锁死要杀进程、插件报错直接把界面搞坏——一位用了一周的用户的原话是「我发现这个 CLI 最脆弱、最容易出错，每装一个插件它就退化一点」。也有人反馈 Windows 支持明显是二等公民。
  • 隐私争议是最伤的一条：有用户审计后发现 web UI 会把请求反代到官方服务器、配置 schema 在每次启动时从官方域名拉取（可据此做 IP 指纹与活动时间戳），必须手动设一串 OPENCODE_DISABLE_* 环境变量才能真正断网自用。HN 上有人因此直接「零信任，立刻删除」。仓库里「默认关闭 sharing」的 issue 自 2026-03 提出后至今仍未关闭。
  • 另一条被反复提的技术账：系统提示约 7k token（还没算 MCP 与工具描述），几轮对话后首 token 延迟明显——这正是不少人转投 Pi 的直接原因。

Cursor CLI：评价最两极的一个

共识：装它的理由通常是「公司只买了 Cursor」。

  • 负面相当直接，有人称它是「我用过的所有软件里用户体验最糟糕的之一」。但同一批帖子里也有人说 CLI 比 Cursor 自家 IDE 快，IDE 会卡住而 CLI 不会。
  • HN 上有条值得注意的反向观察：跑 Opus 时 Cursor 反而更快，「Claude Code 每两分钟就要卡一下」。另一条相反的说法是 Cursor 会对提示做削减以省 token，因此同一个模型经 Cursor 调用的产出不如直接用 Claude Code / Codex。这两条都来自个人体感，没有可复现的测法。
  • 最常见的真实动机是采购而非偏好：公司只报销 Cursor 的情况下，CLI 是最接近 Claude Code 的替代品。还有企业用户指出 Anthropic 不向 enterprise/team 提供 Claude Code 订阅、只能走 API 计价，买 Cursor 企业席位反而更便宜、额度更可预期。
  • 社区里也有人提醒：Anthropic 条款禁止用其服务开发竞品，而 Cursor CLI 显然与 Claude Code 构成竞争——这层法律关系值得留意，但目前没有实际动作。

Kimi Code：性价比明确，可靠性未定

共识：便宜得改变了工作流的经济性，但别拿它跑高风险任务。

  • 成本是压倒性优势。K3 官方价 $3/MTok 输入（缓存命中 $0.30）、$15/MTok 输出，约为 Opus 4.8 的一半；订阅 $19 起，配额按周刷新而非按天——这一点被反复称赞，因为真实的 agent 工作就是有的天狂跑、有的天只读代码。有测算称 1000 万输出 token 的月度负载，K 系列约 $280/天而 Opus 4.7 约 $2500/天。
  • 独立评测互相矛盾，别只看一个：Artificial Analysis 综合排名把 K3 放在第 4（57.1 分）；Arena 的前端代码竞技场里 K3 排第 1，分数高于 Fable 5 与 GPT-5.6 Sol。但 Semgrep 的代码安全测试里 K3 精确率 0.684，明显低于 GPT-5.6 Sol 的 0.880 与 Opus 4.8 的 0.910——误报多。另有对抗性测试称 K3 失败率 36% 对 Opus 4.8 的 8%，不过该测试是专门冲着 K3 已知弱点设计的，日常差距应小于此。
  • 最该重视的是 Moonshot 自己写的三条限制：K3 依赖完整的 thinking history 回传，会话中途从别的模型切到 K3 会导致输出不稳定；K3「过度主动」，意图模糊时会替你做决定，删文件、部署、付款这类动作必须在 AGENTS.md 里写死边界；官方直接承认整体用户体验仍落后 Claude Fable 5 与 GPT-5.6 Sol。厂商肯把这些写进发布公告，比第三方测评更值得信。
  • 工程上的好消息：MCP 配置可直接复用 Claude Code 的，无需改写；实现了 ACP，Zed / JetBrains 能直接把它当后端 agent 使唤。数据驻留方面 API 在中国境内，按自己的合规要求判断。

读这些评价时的两个陷阱：一是时间戳——这些工具的迭代以周计，半年前的「X 比 Y 强」基本失效，本节已尽量只取 2026 年 3 月之后的发言；二是幸存者偏差——会发帖的人要么刚迁移完（急于合理化决定），要么刚被坑（情绪最盛），安静用着没事的沉默用户不会出现在样本里。把这些当作「有哪些失败模式存在」的清单来读，比当作排名来读有用得多。

按你的处境选

已在用 Claude Code + Codex 先加 opencode，别急着换

两个大厂 CLI 已经覆盖了主力场景，第三个的价值在于「模型无关」这一条：当某家限流、降智或涨价时你有退路。opencode 是当下最稳的开源底座（191k star、MIT、当天仍在提交），且认 AGENTS.md、支持 Agent Skills 与 MCP，迁移成本最低。注意它已无法用 Claude 订阅登录。

吃过 context 亏 / 重度自定义 Pi

系统提示压到 1000 token 以内（主流 agent 通常 7000–10000），靠「lazy skills」——每个能力平时只占一行描述，真正调用时才加载完整指令和工具 schema。四个核心工具 + TypeScript 扩展，缺什么让它自己写。适合把 agent 当可编程底座而不是成品软件的人。

想要免费额度 Antigravity CLI

Gemini CLI 的强制继任者，对所有人开放且免费，支持从 Gemini CLI 一次性导入扩展、skills 与设置。代价是闭源、配置文件从 GEMINI.md 换成 AGENTS.md、且 Google 自己承认「上线时没有 1:1 功能对等」。

CI / 批量无人值守 Droid 或 Copilot CLI

droid exec 为非交互批处理而生，$20 起；Copilot CLI 的优势是原生读写 GitHub issue 与 PR，如果你的待办本来就跑在 GitHub Issues 上，这条链路最短。两者都需要订阅，不能白嫖。

不想被任何厂商绑住 Goose

Block 已把它交给 Linux Foundation 旗下的 Agentic AI Foundation 治理（仓库现在挂在 aaif-goose 组织下），Apache-2.0、Rust、MCP 原生、支持 15+ provider 含 Ollama 本地模型。治理中立性是其他项目给不了的。

按量付费、拒绝订阅 Amp

Sourcegraph 出品，纯 PAYG 信用点、个人与团队零平台加价、$5 起充。三档模式（deep / smart / rush）自动路由模型，省去「这个任务该用哪个模型」的决策成本。闭源，但成本结构最透明。

调研日期 2026-07-30。star 数、许可证与最近提交时间由 GitHub API 当天拉取；定价与形态来自各家官网，可能随时变动，下单前请以官网为准。本报告不含实测跑分——公开榜单（Terminal-Bench、SWE-bench）的分数高度依赖模型而非 harness 本身，换一个模型排名就会翻转，因此这里只记录工具形态与工程事实。

选型提醒：这个领域 2026 上半年发生了 opencode 迁移组织、Goose 转入基金会、Roo Code 自行归档、Gemini CLI 停服四起变动，任何超过三个月的推荐清单都应重新核对。给 agent 开放 shell 执行权限前，确认它支持沙箱或审批模式；在已登录凭据的环境里跑自动执行有实际风险。
