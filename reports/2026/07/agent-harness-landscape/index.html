Harness 生态
全景 2026

2026 年 GitHub 上搜 “harness”，出来的东西彼此毫不相干：一个 CI/CD 平台、一堆模型评测框架， 和一个刚被命名半年、却已经堆出几十万 star 的新物种 —— agent harness。 这份报告把三者拆开，把新物种的 40 个热门项目按实测数据排好，并附上 Hacker News 上 支持与唱衰的一手声音。

一句话结论

GitHub 上的 “harness” 现在压倒性指 agent harness —— 即包住大模型的那层脚手架： 上下文投喂、工具接口、计划产物、验证回路、记忆与沙箱。

这个词由 OpenAI 在 2026 年初正式命名为一门学科，随后 3–4 月 GitHub 上集中爆发出 一整批 awesome list、教程书和实现。老牌同名项目 Harness.io（CI/CD，37.5k star） 和 lm-evaluation-harness（模型评测，13.5k star）虽然仍在活跃，但在搜索结果里已被新物种淹没。

要点在于：最主流的 harness 实现，描述里根本不写 “harness” 这个词。 只按关键词搜会漏掉 openclaw（384k）、superpowers（264k）、hermes-agent（223k）这些真正的头部。

先消歧：三个 harness

同一个词，三个互不相干的技术领域。看 star 排行前先分清自己要找哪个。

① Agent Harness

包住模型的脚手架

agent loop、上下文压缩、工具设计、skills / MCP、权限沙箱、记忆、验证回路。 本报告的主线，2026 年的热点所在。代表：openclaw、opencode、deepagents。

② Harness.io

CI/CD 开发者平台

harness/harness，2014 年建仓（前身 Drone / Gitness），Go 编写，Apache-2.0， 37,565 star。源码管理 + 流水线 + 云端开发环境 + 制品库。与 AI 无关。

③ Evaluation Harness

模型评测框架

EleutherAI 的 lm-evaluation-harness（13,472 star）与 bigcode-evaluation-harness。这里的 harness 是测试学里的老义 ——“测试台架”，早于 AI agent 用法。

另有一批纯属撞词的结果，例如 SnapKit/Masonry（iOS 布局库，描述里恰好有 “Harness the power of AutoLayout”）。 搜索时建议用 "agent harness" 加引号，或直接按下面的分层表找。

这个词是怎么火起来的

harness 作为“测试台架”是老词。但把它抬升成一门工程学科，是 2026 年的事， 而且有明确的官方推手。

  • 此前

    Prompt engineering → Context engineering。社区已在讨论“模型之外的东西才是胜负手”，但没有统一名字。

  • 2026 年初

    OpenAI 发布 Harness Engineering 与 Unrolling the Codex Agent Loop， 把 harness engineering 定义为一门学科并拆解 Codex 的 agent loop。 这是术语被正式命名的节点。

  • 同期

    Anthropic 发布 Harness Design for Long-Running Application Development 与 Building Effective Agents。两家头部同时给这层命名，词汇迅速标准化。

  • 2026-03 下旬

    GitHub 集中爆发：awesome-harness-engineering（3-29 建仓）、 learn-harness-engineering（3-29）、awesome-agent-harness（3-30）、 中文 42 万字的 claude-code-book（3-31）、harness-books（4-01）。 一周之内五个同主题仓库，典型的术语跟风窗口。

  • 2026-04 起

    研究界跟进：Agentic Harness Engineering (AHE) 论文上 arXiv， 提出冻结模型、只演化 harness；Stanford IRIS Lab 的 meta-harness 同期发布。

  • 2026-07

    xAI 发布 grok-build（7-14 建仓，两周 23.5k star），描述直接自称 “coding agent harness and TUI”。大厂在产品命名上采用了这个词。

注：两个 openai.com 链接经当天 curl 校验返回 403 —— 这是 Cloudflare 对自动化请求的拦截， 域名与路径有效，浏览器可正常访问。Anthropic、arXiv、Terminal-Bench 三个链接均实测 200。

harness 到底包含什么

社区已经收敛出一套相当一致的组件清单。以下分类取自 awesome-harness-engineering 的目录结构，可作为评估任何一个 harness 项目的检查表。

Agent Loop

最内层的对话-工具-观察循环。决定 agent 何时停、何时追问、何时重试。

Planning & 任务分解

Plan.md / Implement.md 这类可复用的计划产物，把长任务拆成可验证的段。

上下文投喂与压缩

决定哪些内容进窗口、何时压缩、压缩掉什么。被公认是效果差异的最大来源之一。

工具设计

工具的粒度、命名、描述与返回格式。HN 上有人实测：给 write 工具加一个必填 reasoning 参数就能改变模型行为。

Skills & MCP

可复用能力的封装与外部服务接入。skills 生态本身已长出 264k star 的 superpowers。

权限与沙箱

pre-tool hook 拦截危险命令、禁止 push main、凭据隔离。安全事故的主要防线。

记忆与状态

跨 session 的项目记忆。claude-mem（89k）、agentmemory（26k）、memU（14k）都在打这一层。

验证回路与 CI

让 agent 自查而不是自称完成。“verified completion” 是多个项目的核心卖点。

可观测性与追踪

把 agent 的每步决策记录下来 —— AHE 论文正是靠这层实现 harness 的自动演化。

几条值得单独记下的事实性发言

  • 订阅与 harness 的绑定差异：“Codex 订阅相比 Claude 的一大优势是你可以配任何 harness 用； 而 Anthropic 坚持 Claude 订阅只能配 Claude Code 自己。” —— OleksandrC, 2026-07-21。 这解释了为什么 cc-switch（多 harness 切换器）能拿到 122k star。
  • harness 是安全事故的责任层：关于 OpenAI 沙箱逃逸事件，有评论主张更准确的标题是 “OpenAI 确认其 agent harness 与安全措施的缺陷让被诱导的 AI 越权” —— therealpygon, 2026-07-22。harness 层正在成为安全归因的焦点。
  • harness 对模型极其敏感：“把 3.5 Flash Lite 插进原本跑 3.1 Flash Lite 的 harness， 完全不工作 —— 不遵循指令，工具调用也不对。” —— lwansbrough, 2026-07-21。 换模型不等于即插即用，这是选型时最容易低估的迁移成本。
  • 提示词的微小改动会影响性能：“升级 pi.dev 后用同一个 Qwen 模型测， 性能比旧版略降……系统提示词的任何细微变化都会有影响。” —— tesnorindian, 2026-07-21。

采集偏差提示：HN 用户以英文技术圈为主，对“新造词”天然偏怀疑； 公开发声者非极满意即极不满，沉默的中间用户不在样本内。上面负面声音的比例， 不代表该技术的实际有效性分布。

选型风险

以下均为当天实测数据能直接支撑的具体风险，不是泛泛的注意事项。

许可证：Trellis 是 AGPL-3.0

mindfold-ai/Trellis（13,351 star）采用 AGPL-3.0，具有强传染性 —— 若接入自有服务并对外提供，可能触发开源义务。同类项目绝大多数是 MIT / Apache-2.0， 这是本批次里唯一的显著许可证异类，商业环境引入前务必过法务。

许可证不明：openclaw、oh-my-openagent

两者 GitHub API 返回许可证为 NOASSERTION（无法识别为标准开源许可证）。 openclaw/openclaw 是本次 star 数最高的项目（384,599）， 许可证不明确意味着使用与二次分发的权利边界需要自行到仓库确认，不能假定为 MIT。

issue 积压：hive 与 hermes-agent

aden-hive/hive 有 1,313 个 open issue，而最后推送停在 2026-05-29， 已两个月无更新 —— 10.8k star 配 5,667 fork 的高 fork 比也暗示大量使用者在各自分叉。 NousResearch/hermes-agent 有 25,891 个 open issue，虽仍在日更， 但相对 223k star 的比例仍属偏高，提问得到响应的期望值应放低。

热度极新，尚未经过时间检验

本表中 star 数前十的项目，除 opencode（2025-04）与 hermes-agent（2025-07）外， 全部建仓于 2025 年底之后；grok-build 建仓仅 17 天便积累 23.5k star。 这个赛道还没有任何一个项目经历过完整的“热度退潮后是否有人维护”的周期。

star 通胀，横比才有意义

2026 年 AI 类仓库的 star 与实际使用者严重脱钩。以 watcher/star 比为例： ECC 0.52%、deer-flow 0.42%、learn-claude-code 0.40% —— 均远低于传统开源项目 常见的 1–3%。这说明整个品类的 star 都被点赞式行为稀释了， 不要把 20 万 star 读成 20 万用户，但同一批次内的相对高低仍有参考价值。

怎么用这份表

按你的实际目的走，不同目的看的是完全不同的几行。

  • 想直接用一个成熟 coding agent → 看“完整 harness 实现”类。 主流是 opencode、openclaw、hermes-agent、pi；对模型中立、想自带 API key 的可看 CodeWhale（Rust，MIT，明确以开放模型优先）。
  • 已经在用 Claude Code / Codex，想增强它 → 看“增强层 / meta-harness”类。 superpowers（skills 方法论）、claude-mem（跨 session 记忆）、wshobson/agents（多 harness 插件市场） 是这层里 star 最高的三个，都不要求你换掉现有 harness。
  • 要在自己产品里嵌 agent → 看“SDK / 框架”类。 deepagents（LangChain 出品，Python + JS 双版本）、strands-agents/harness-sdk（Apache-2.0，多云多模型） 是意图最明确的两个；parlant 专攻可控的对客交互。
  • 想搞懂原理、自己写一个 → 看“学习 / 方法论”类。 rasbt/mini-coding-agent 是最小可读实现（但已停更于 2026-04）； learn-claude-code（72.7k）与中文 claude-code-book（42 万字）是体量最大的两份拆解材料。
  • 关心前沿方向 → 看“研究”类。AHE 的思路值得注意：冻结模型，只让 harness 自我演化， 在 Terminal-Bench 2.0 上以 84.7% 排到第 3，并称冻结后的 harness 能迁移到 SWE-bench-Verified。 这是对“harness 不重要”那派最直接的反证。

一条务实的判断

社区两派的分歧其实可以调和：harness 不重要的说法，在模型能力足够覆盖任务时成立； harness 重要的说法，在任务超出模型单轮能力时成立。 任务越长、越需要跨 session 记忆、越要求可验证的完成度，harness 的边际价值越高。 反过来，如果你的用途是几十行的一次性脚本，装再多 skill 也只是 HN 上说的“折腾排气管”。
