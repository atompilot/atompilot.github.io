最贴近采购清单 · 值得验证

taobao-sourcing-mcp

带采购 skill；源码有搜索、SKU 与价格关联、评价和 XLSX 导出，能作为淘宝端的实现参考。

优点：SKU 表与商品、评价分表，处理多规格比较。

缺点：仅淘宝 / 天猫；导出的比较表仍需补需求数量、运费和最终推荐。深度价格读取超过 24 个 SKU 会跳过，部分读取失败可能保留原价格，接入时必须记录每个价格的口径。

开放 Issue #1（2026-08-16）有一位使用者报告核心流程可用，也提出 XLSX 文本注入和依赖兼容问题；这是一条第三方体验，不能代表稳定性。查看 Issue。仓库未检出 LICENSE，复制或分发代码前需确认授权。

淘宝 + 京东 · 值得验证

JD-Taobao-MCP

本地 Playwright 浏览器工具，搜索和提取商品、店铺、参数、部分评价；源码默认阻止购买、加购等动作。

缺点：不覆盖闲鱼；读取价格字段不等于完成所有 SKU 的匹配与最终到手价确认，仍需采购 skill 组织核对和导出。

推荐的采购 skill 应该怎样工作

my-procurement 是建议的入口名称，本次未创建或安装。它负责跨平台采购方法，数据读取交给浏览器或经过验证的 MCP。

01 需求用途、规格、数量、预算、全新 / 二手、交期与收货区域。
02 搜索每项从淘宝、闲鱼等来源找候选；记录覆盖范围。
03 核对指定 SKU、含税口径、包装数量、运费、成色、退换与兼容。
04 清单推荐、备选、待询价、总额与证据时间；购买前复查。

第一版主路径：复用现有浏览器工具读取可见商品页，暂不依赖上述新 MCP。优点是能先验证整个采购方法，并保留页面依据；缺点是会遇到登录、验证码和网页变化，尚未实测的账号访问不能承诺无人值守。

后续替换：如果真实样本证明淘宝搜索或 SKU 读取反复需要人工整理，再引入经审查的专用适配器。保持同一份采购清单格式，避免每接入一个平台重新设计输出。

浏览器与 MCP 的共同限制：工具不会自行保证“同款”。标题相似只能作为候选，必须核对型号、接口、尺寸、套装内容和成色。网页推荐排序和样本最低价都不能代表全市场最低价。

淘宝采购项目作者明确提示自动化访问的账号限制风险，闲鱼买家项目也提示反爬和会话过期。登录与验证码需要用户在浏览器内处理；降低访问频率不能保证账号安全。采购 skill 不应承诺持续无人值守。

清单字段记录要求
物品 / 用途 / 数量区分需求件数、每包件数、购买包数；套装列明内含物。
指定型号 / SKU保存商品 ID、SKU 标签或 ID、平台、店铺与商品链接。
价格 / 运费 / 优惠区分标价、所选 SKU 页面价、卖家报价和用户确认的结算价；运费未知不能填零，条件优惠单独列。
全新 / 二手证据卖家描述与已确认事实分开；二手记录维修史、故障、缺件、测试证明和售后待确认项。
推荐 / 备选 / 待询价说明满足哪些要求、为何推荐、什么情况下换备选；关键字段缺失时保持待确认。
合计与时效商品合计按购买单位计算，运费按订单或卖家核对避免重复；显示已知金额与待确认费用，不用未知项计算虚假的完整总价。
来源与时间每条报价附观察时间和可回读链接；报价变化或下架后重新核验。

最终交付三份内容：采购清单（推荐与备选）、候选比价表（包含淘汰理由）、待确认与询价草稿。保存为本地 Markdown / CSV / XLSX；实际报价、聊天和采购记录默认保留本地。

一次真实采购就能检验的最小实验

  1. 选择 2–3 种实际要买的物品，至少包含一个多 SKU 商品和一个二手候选。
  2. 每项尽量找 3 个候选，覆盖淘宝与闲鱼；搜索失败或没有合适商品时明确写出缺口，不补模拟结果。
  3. 逐项核对具体 SKU、数量单位与价格来源；二手成色和功能证据缺失时放入待询价。
  4. 输出清单并人工复查。通过标准：链接可回读、规格一致、价格口径明确、计算正确、未知项完整；涉及最终成交价必须有结算或卖家报价依据。

实验失败时定位具体环节：访问失败、价格提取错误、规格匹配错误或清单计算错误。验证码交回用户处理；没有验证成功的数据入口不能承诺自动完成。
