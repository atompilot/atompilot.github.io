循环最后一步，会决定收集到什么

卡片的背后，是一份结构化记录

下面把“Text → 按换行拆分”的核心动作转成 JSON 展示。你不用先学会这段代码，才能在手机里搭出它。

{
  "WFWorkflowActions": [
    {
      "WFWorkflowActionIdentifier": "is.workflow.actions.gettext",
      "WFWorkflowActionParameters": {
        "UUID": "11111111-1111-4111-8111-111111111111",
        "WFTextActionText": "apple\nbanana\norange"
      }
    },
    {
      "WFWorkflowActionIdentifier": "is.workflow.actions.text.split",
      "WFWorkflowActionParameters": {
        "text": {
          "WFSerializationType": "WFTextTokenAttachment",
          "Value": {
            "Type": "ActionOutput",
            "OutputUUID": "11111111-1111-4111-8111-111111111111",
            "OutputName": "Text"
          }
        },
        "WFTextSeparator": "New Lines"
      }
    }
  ]
}
先只认这 3 个字段

WFWorkflowActions：按执行顺序排列的动作。
…Identifier：动作的内部名称。
…Parameters：这块动作的设置。

再认一条“连线”

Text 的 UUID 与拆分动作的 OutputUUID 一致，表示拆分动作取这一步的输出。这个 UUID 是动作标记，不是手机 phoneId。

字段形态依据已有生成器与原厂旧版下载工作流核对，属于样本格式，不作为 Apple 承诺稳定的公开编程接口。此处只展示核心动作，省略完整文件元数据与签名，也未作为新捷径进行手机导入验证。

会看卡片，就能理解生成流程

可视化编辑器呈现卡片；工作流内部保存结构化数据；分发时还可能有签名封装。

动作与参数
→
工作流 plist
→
签名分发文件

plist 是 Apple 常用的数据存储格式，可用 XML 或二进制表示。JSON 在本课只是方便人阅读的展示方式；把 JSON 改成 .shortcut 后缀，不代表就能安装。

已取得的原厂旧版样本：未签名工作流以 bplist00 开头；签名分发文件以 AEA1 开头。因此不能假定每个下载的 .shortcut 都可以直接当普通 plist 读取。

Mac 的签名命令示意
shortcuts sign --mode anyone \
  --input unsigned.shortcut \
  --output signed.shortcut

这里只讲流程，未执行签名。Apple 会收到副本进行验证；命令可用不等于文件已通过手机安装或功能验收。

和 phoneId 的关系

同一个模板可以留出 Text 配置，接收者定制时填写 phoneId。这与服务器为每台手机改写工作流后再签名，是不同的生成流程。

导入问题可填配置；Manager 替换更新能否保留答案，需要对实际安装路径验证，不能由语法推断。

不对劲时，看这 4 件事
  1. 输入来源选对了吗？
  2. 拿到的是文字、列表，还是图片？
  3. “查找照片”的相册和范围选对了吗？
  4. 先临时加“快速查看”，看当前输出。
Text 里写 Python，不会执行 Python

Text 中填 text.splitlines()，输出就是这段文字。要拆分，用“拆分文本”动作；界面中的变量要插入真正的变量标签，手打 [PhoneId] 或 ${{PhoneId}} 不会自动成为引用。
