主动式与被动式 Agent
谁来发起下一轮？

2026-11-02 · 按官方文档核对 · 图中流程为概念示意

被动式：你叫它，它才开始。主动式：你先交代目标，它之后能在合适的时间或事件发生时，自行检查并决定下一步。

这里按产品使用方式理解“主动／被动”，不是严格统一的学术分类。例如，先交代“帮我盯住项目进展”：被动模式要等你问“有什么卡点”；主动模式会定时检查，发现新卡点后再通知你。

两个容易混淆的地方

主动性和执行自主性是两件事。你下一个命令，它自己连续完成二十步，说明执行自主性强；但下一项工作仍等你发起，就仍是被动使用模式。同一个 Agent 可以同时支持两种模式。

定时自动化也不一定需要 Agent。每天九点照固定规则生成报表，普通工作流就能完成；如果它还要理解新情况、判断是否值得处理、选择工具和下一步，才需要 Agent 的判断能力。主动模式应提前说清：什么时候检查、能做什么、何时通知你。

目前值得看的六个项目

按用途选择，不作“综合最强”排名。以下是官方能力核对，未对这六套系统做同场实测。

项目更适合研究什么当前能力与边界
OpenClaw长期个人助手聊天入口、定时检查、事件触发与结果投递。当前官方已把 heartbeat 监控统一到普通 automation jobs，旧教程的配置需核对。官方机制
Hermes Agent记忆与技能积累跨会话记忆、可复用 skills，并支持定时／事件任务。经验沉淀在记忆和技能中，不等于自动训练模型。任务机制
Letta／Letta Code有持续记忆的助手共享记忆、后台整理经验、channels 与 schedules。旧 LettaBot 已归档；本地定时任务需要对应机器上有活跃 Letta 会话。运行条件
OpenHands Agent Canvas持续工程任务当前主仓库是可自托管的编程 Agent 控制台，可从对话启动任务，也可按时间或 webhook 触发，连接本地、远程或云端执行环境。当前定位
LangGraph自己开发 Agent提供状态持久化、持续执行与人工介入等编排能力。属于开发底座；何时启动、目标是什么，由应用定义。官方定位
n8n把业务系统接起来可用 Schedule Trigger 启动流程，再接 AI Agent 节点选择工具。它是自动化平台，整个工作流不必都交给 Agent 判断。Agent 节点

我的阅读建议：想体验“交代一次、后续替我盯着”，先看 OpenClaw、Hermes；想深入记忆机制，看 Letta；想把主动能力做进自己的产品，看 LangGraph，已有固定业务流程则先看 n8n；想围绕代码库持续安排工作，看 Agent Canvas。这是按上述功能作的用途判断，不代表实际效果排名。

来源与适用边界

  • OpenClaw：Automation、Heartbeat migration，确认定时、事件、投递与现行迁移说明。
  • Hermes：Scheduled Tasks、Persistent Memory及官方仓库，确认调度、记忆和 skills。
  • Letta：Memory & dreaming、Schedules、Channels及LettaBot 归档说明。
  • OpenHands：当前官方 README，确认 Agent Canvas 定位、执行环境与定时／webhook 自动化。
  • LangGraph：Overview，确认其为编排框架与运行时。
  • n8n：Schedule Trigger、AI Agent，确认触发与工具选择分别由什么承担。

资料核对日期：2026-11-02。产品版本与命名会变化；功能存在不代表特定业务已验证。例子为通用教学示意，不包含私人项目资料。
