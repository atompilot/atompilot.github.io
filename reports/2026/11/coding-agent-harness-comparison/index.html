四个会写代码的 AI
怎么记住你说过的话

2026-11-16 · 对照各家官方文档与公开实测 · 数字随版本变化，未确认处已标注 · 图为示意

它们的差距不在模型多聪明，而在「窗口只有一扇，任务比窗口大」时怎么办。同样一场三小时的重构，四家用了四种完全不同的遗忘策略。

先说清一件事：为什么一定会「记不住」

AI 一次能读的字数有上限，这个上限叫上下文窗口（单位是 token，中文大约一个字一个 token）。窗口里同时挤着三样东西：

  • 固定开销：系统提示、工具说明、项目规则文件。每次请求都要重新带上。
  • 对话历史：你说过的话、它说过的话、它改过的代码。
  • 工具输出：跑一次测试的日志、读一个文件的全文、搜索结果。这一项涨得最快。

窗口满了只有两种结局：要么报错停下，要么悄悄忘掉开头——你前面说过的约束就这么没了。所以每个 harness（模型外面那层「脚手架」）都必须回答同一个问题：该丢什么、丢到哪、丢了以后还能不能找回来。

答案基本只有四种动作，四家的区别就是这四种动作的配比不同：截断（砍掉多余输出）、落盘（写进文件，只留路径）、摘要（让模型把旧对话压成一段笔记）、隔离或搬家（交给子代理、换个干净会话、搬到云上）。

Claude Code：会做笔记的同事

它的答案是把历史写成摘要，再补上最近的现场。窗口快满时自动压缩：把前面的对话换成一份结构化摘要，然后重新注入系统提示、项目规则、技能说明，并重新读一遍最近改过的几个文件——这一步很关键，因为摘要会丢细节，但文件内容不会骗人。

压缩时发生什么

据官方文档与社区实测；触发点可配置

接近窗口上限→生成摘要→重注入 CLAUDE.md / 记忆→重读最近 5 个文件→继续

记忆分两层。手写层是 CLAUDE.md：企业级、用户级、项目级、项目本地四层拼接而不是覆盖，所以公司规范和个人习惯能同时生效；子目录里的规则只在你碰那个目录时才加载。自动层是 ~/.claude/projects/<项目>/memory/MEMORY.md，相当于 Claude 自己维护的索引，每次会话只读前 200 行或 25KB——它知道「有这本笔记」，需要时再翻。

代价也很直接。第三方实测显示，压缩后的摘要能保住约 77% 的决策，但只剩约 0.2% 的具体命令；早期约束和多步任务状态最容易蒸发。另外沙箱默认是关的，安全靠逐次权限确认兜底，弹窗多也是它被抱怨最多的地方。

Codex：一条有门禁的流水线

它的答案是把压缩做成服务端能力，把执行关进系统沙箱，把长任务搬上云。压缩有两条轨：优先走服务端的 compaction v2（官方口径保留约 64K token 的近期消息），失败才回落本地摘要（约 20K）。这样压缩本身不占本地算力，也更容易在不同入口之间保持一致。

规则文件走另一套逻辑：全局 ~/.codex/AGENTS.override.md 优先于 AGENTS.md，项目层从仓库根一路拼到当前目录，越近越靠后；总量有 32KiB 硬顶，防止你把整个 wiki 塞进提示词。

它的「长期记忆」不是靠你手写文件，而是一条后台管线：会话空闲足够久（约 6 小时）、额度还剩得够（约 25%）、只看 30 天内的对话，每次最多提炼 16 条。官方自己说得很清楚——它是召回层，替代不了 AGENTS.md。

最不一样的是默认值：沙箱默认开，macOS 用 Seatbelt，Linux 用 bwrap + seccomp，工作区模式默认断网。所以它敢在你不在的时候跑；真跑不完，codex cloud 把任务交出去，睡一觉回来 apply 结果。代价是订阅窗口（500K）小于 API 标称（1.05M），且超过约 272K 输入按 2 倍计价。

Grok Build：把桌子换大，家具直接借邻居的

它的答案最省事：窗口给大一点，生态直接兼容。2026 年 5 月才有官方 CLI，但一上来就零配置读 Claude 那一套——CLAUDE.md、.claude/ 下的技能与市场、MCP 配置都能直接用。你从 Claude Code 迁过去，几乎不用改文件。

默认模型是旗舰 grok-4.7（500K），而不是专门的小上下文代码模型；更老的 4.3 反而有 1M。压缩是标配的自动 + 手动 /compact，但保留策略官方没细说。记忆是明显短板：只有实验性的 memory 开关，没有 Claude 那种「自己写笔记」的成熟体系。

两个要留意的成本细节：prompt 超过 200K 后单价整体翻倍（$2/$6 变 $4/$12），以及订阅是共享周池，重度使用容易提前见底。沙箱也有，但默认关闭。

DeepSeek Harness：把「历史」和「上下文」拆开

它的答案最工程化：历史是一本只追加的账，上下文只是这本账在某一刻的投影。压缩不是删除，而是往账本上追加一条「用这段摘要替换那一段」的记录——原始事件还在盘上，被替换的范围也记得清清楚楚，所以可审计、可回溯、崩溃后可重建。

门槛是这样算的：取「窗口的 80%」和「窗口减输出预留再减 64K 余量」里更小的那个。1M 窗口下约 727K 才触发摘要，摘要后逐字保留最近约 127K。在那之前，它先用两种几乎不花钱的手段：单个工具结果超过约 12,500 token 就写进文件，只留首尾预览和路径（模型需要时自己 read／grep）；真到了压缩，再先把超长工具结果按头 4096 / 尾 1024 字符剪一遍——剪完够用就不调用模型写摘要了。

记忆的层次也最多：AGENTS.md 提供项目约束；技能只在目录里放一行摘要，正文按需加载（渐进披露本身就是省 token）；目标（goal）是独立的状态机，能跨轮次续跑、记录修订号，连续三轮同一阻塞才算「卡住」；子代理默认不共享上下文，只回结果——隔离本身就是一种记忆管理。

它的短板在「量得不准」：token 估算按每 token 四字符的启发式，对中文和 JSON 会低估，理论上压缩会来得偏晚。好处是这套东西全是插件，压缩后端、剪枝策略、权限档位都能换。

同一件事，四种现场

假设你丢给它一个三十万 token 的老项目，说「把支付模块重构成异步，别改对外接口」，然后离开三小时。

Claude Code

还早，窗口没满，它先把「不要改对外接口」记进项目记忆。跑到第九十分钟窗口到顶，压缩一次，摘要里留下结论、丢掉你当初举的反例；它重读最近改的五个文件，把现场捡回来。你回来时它还知道目标，但可能问你「刚才说的那个兼容层要保留吗」。

Codex

因为默认断网，它不会偷偷装依赖；跑测试碰壁会停下来问你。窗口到 500K 附近触发服务端压缩，保留最近 64K 的上下文。三小时没跑完，它把任务提交到云端继续，第二天你在本地 apply 结果，再看一遍 diff。

Grok Build

直接读你现成的 .claude/ 技能，零配置开工。500K 窗口够撑到重构过半，超过 200K 之后每一步都按双倍价钱算。真满了靠自己 /compact，或者你手动重开会话，把关键结论贴回去。

DeepSeek Harness

每次跑测试的几万行日志早就落盘，模型只看到「结果太长，存在这个路径」。727K 才第一次摘要，历史仍在账本上。你不放心，可以回头查它到底哪一步替换了什么——因为压缩是可查的事件，不是一次不可逆的遗忘。

抽象一层：四种「记忆观」

  • 笔记式（Claude Code）：让模型自己写笔记，下次先读索引。优点是自然，缺点是笔记质量取决于模型自觉。
  • 流水线式（Codex）：把记忆变成后台任务，加空闲时长、额度、条数、时间窗四道限制。优点是可控，缺点是不及时、默认还关着。
  • 兼容式（Grok Build）：不发明记忆格式，复用别人的文件约定。优点是迁移零成本，缺点是没有自己的深度。
  • 账本式（DeepSeek Harness）：记忆是事件日志，上下文是投影。优点是可信、可审计、可重放，缺点是概念多、要理解「替换不是删除」。
一个共同结论：四家都不指望「对话」替你记事。真正稳定的记忆只有两种载体——仓库里的文件（AGENTS.md、CLAUDE.md、技能、代码本身）和盘上的日志（会话记录、落盘的工具输出）。写进这两处的东西才活得过三次压缩。

不管选哪家，有四件事现在就能做，效果比换工具大：

  1. 把「永远成立」的约束写进 AGENTS.md 或 CLAUDE.md，别在对话里重复第十遍。
  2. 长任务拆成有明确验收点的阶段，每阶段结束让它把结论写进文件。
  3. 重要产出（设计决定、接口清单、失败原因）落盘，不要只活在对话里。
  4. 知道它的压缩触发点在哪，快到时主动收尾或开新会话，比被动画一刀更划算。
